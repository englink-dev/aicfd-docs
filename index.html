aicfd#

CFD 해석 결과를 신경망으로 예측하는 모델 5종의 기술 문서다. 건물 외부 유동, 사무실 실내 공조, 비강 기류를 각각 다루는데, 다루는 대상은 달라도 학습 골격은 하나를 같이 쓴다.

모델마다 독립된 repo 로 관리하고 배포한다. 이 superproject 는 배포용이 아니라, 다섯을 나란히 두고 한자리에서 읽기 위한 것이다.

용어#

문서 전체가 아래 표기를 따른다. 코드 식별자는 등폭체(nondim), 개념어는 일반 서체다.

모델 이름#

repo 이름을 그대로 쓰고 줄이지 않는다. 접두사가 프로젝트 계열을 구분하며, 줄이면 이름이 충돌한다 — 예컨대 비강 체적 유동을 다루는 aicfd-nasal-physical 이 추가되면 비강 표면 을 다루는 aifem-nasal-physical 과 뒷부분이 같아진다.

  • aicfd- — 유동 해석 결과의 체적 단면을 예측한다. 격자 표현.
  • aifem- — 유한요소 해석 결과의 벽면 flux 장을 표면 mesh 위에서 예측한다. WSS 는 그중 첫 필드이고, 수증기 질량 flux 와 벽면 열 flux 가 추가될 예정이다.
repo 대상 예측 대상
aicfd-building-physical 건물 외부 유동 물리량 단면
aicfd-indoor-physical 사무실 1개 실내 물리량 단면
aicfd-building-pixel 건물 외부 유동 렌더 이미지 단면
aicfd-nasal-pixel 비강 유동 렌더 이미지 단면
aifem-nasal-physical 비강 표면 vertex 별 표면 flux (현재 WSS)

두 개의 분류 축#

축 값 뜻 해당 모델
표현 grid 필드를 정규 격자 이미지 (b,c,h,w) 로 다룬다 aicfd-building-physical, aicfd-indoor-physical, aicfd-building-pixel, aicfd-nasal-pixel
mesh 삼각형 표면 mesh 의 vertex 위에서 직접 다룬다 aifem-nasal-physical
target 물리량 예측 대상이 실제 물리 단위 값(m/s, Pa, °C, WSS) aicfd-building-physical, aicfd-indoor-physical, aifem-nasal-physical
렌더 이미지 예측 대상이 이미 색으로 렌더된 이미지 바이트 aicfd-building-pixel, aicfd-nasal-pixel

두 축의 교집합을 부를 때는 물리량-grid(aicfd-building-physical, aicfd-indoor-physical), 물리량-mesh(aifem-nasal-physical), 렌더-grid(aicfd-building-pixel, aicfd-nasal-pixel) 로 쓴다.

'physical' 이라는 단어의 세 가지 쓰임

  • repo 이름의 -physical 접미사
  • 텐서 공간 이름 physical — dequantization 을 거친 물리 단위 텐서 (데이터 공간)
  • 위 표의 target 축 값 "물리량"

등폭체 physical 은 셋 중 공간을 가리킨다.

공통 아키텍처#

여기서부터는 다섯 모델이 함께 쓰는 골격이다. 각 repo 가 따로 배포되기 때문에 이 골격은 공용 패키지가 아니라 repo 마다 들어 있는 복사본이다. 그래서 한쪽을 고치면 나머지에도 같은 수정을 옮겨야 한다 (패키지 디렉터리는 aifem-nasal-physical 만 aifem/ 이고, 나머지는 aicfd/ 다).

학습 루프#

Workspace(fold 단위) → Trainer(epoch 단위) → finalize_fold

scripts/train.py 가 fold 를 순회하고, 각 fold 안에서 epoch 을 돌리며 검증 지표가 개선되지 않으면 조기 종료한다 (patience 초과 시 최고 성능 checkpoint 로 복원). fold 종료 시 post-hoc EMA 후보를 골라 test 를 돌리고 결과 csv 를 쓴다.

데이터 적재#

구성요소 단위 역할
Dataset (utils/dataset.py) 샘플 1개 h5 읽기, 윈도우/케이스 샘플링
Collator (utils/collator.py) 배치 1개 스택, crop 또는 pad, 증강, 공간 변환, 조건 입력 정규화

Collator 는 CPU 에서 float32 로만 동작하고, GPU 이동은 to_device 가 일괄 처리한다. Dataset 변종은 단일 슬라이스(DatasetImage), 깊이 윈도우(DatasetDepthSeq), 케이스 전체(DatasetDepthCase) 세 가지다.

aifem-nasal-physical 은 Collator 가 없다. mesh 는 vertex 수가 가변이고 희소 연산자를 함께 들고 다녀 하나의 밀집 텐서로 묶을 수 없다. Dataset 이 기하 연산자 사전계산과 target 정규화까지 마친 샘플 dict 를 내보내고, 배치는 collate_fn=list 로 만든 파이썬 리스트다.

모델 기반 클래스#

models/base_model.py 의 BaseModel 이 train/val/eval 루프, 온라인 가중치와 EMA 가중치를 바꿔 끼우는 컨텍스트 매니저, checkpoint 생성·적재를 담당한다. 확산 계열은 BaseModelPostHocEMA 를 써서 여러 EMA 표준편차 후보를 사후 재구성해 최적을 고른다. 회귀 계열은 일반 SWA 형태의 EMA 를 쓴다.

Metric 컨테이너#

Metric 은 {예측 필드: {지표 이름: [값]}} 구조의 dict 서브클래스로, 배치 누적(.sum)·가중(.mul)·이름 병합(.extend) 만 제공한다. 지표의 정의와 해석은 Metric 문서 에 있다.

공유 범위#

파일 다섯 모델에서
utils/prefetch.py, utils/train_helper.py 동일
utils/scheduler.py, utils/ema.py grid 4종은 scheduler 가 동일하고, 그중 aicfd-nasal-pixel 을 뺀 3종은 ema 까지 동일하다. aifem-nasal-physical 은 scheduler 를 WarmupConst 로 축약하고, aicfd-nasal-pixel 은 ema 의 eval_index 를 nn.Buffer 로 보관한다
utils/metric.py, utils/model_helper.py, models/base_model.py 절반만 공통. 나머지는 표현과 정규화 방식에서 달라진다

check_drift.sh 가 위 구분대로 검사한다.

데이터 공간#

디스크에 저장된 값이 그대로 신경망에 들어가지는 않는다. 어느 모델이든 저장값을 크기가 O(1) 인 학습 공간으로 한 번 옮기고, 평가할 때 그 변환을 그대로 되돌린다. 변환은 전부 invertible affine 이라 되돌리는 데 오차가 없다. 변환의 모양은 다섯 모델이 다르지 않다. 그 affine 을 어떻게 정하느냐만 다르다.

dequantization (grid 공통)#

grid 모델은 저장값이 uint16 이라, 무엇을 하든 먼저 물리 단위로 풀어 놓는다.

xphys​=65535amax​−amin​​u+amin​,u∈{0,…,65535}

amin/amax 는 필드별 저장 범위이고 cfg.dataset.maxima 로 넘어온다. velocity 는 풀고 나서 u/v/w 3채널로 나뉜다. 렌더-grid 는 저장값이 이미 이미지 바이트라 이 단계가 아예 없다.

nondim#

물리 단위로 풀어 놓은 값(렌더-grid 라면 저장 바이트)을 다시 신경망이 입력으로 받는 O(1) 공간으로 옮긴다. 이것도 invertible affine 이다. 모델마다 다른 건 계수를 어떻게 잡느냐뿐이다.

모델 계수 결정 목표
aicfd-building-pixel, aicfd-nasal-pixel 고정 상수 x=2552​u−1 값이 [−1,1]
aicfd-building-physical 기준 풍속별 표본 통계 표준편차 1
aicfd-indoor-physical 채널별 전역 통계 + 기준온도 차감 표준편차 1
aifem-nasal-physical 물리 유도 지수 + 해석 설정값에서 온 상수 면적가중 중앙값 32

식과 유도, 통계를 어디서 구하는지는 nondim 에 모아 두었다.

nondim 이라는 이름

nondim 은 특정 수식의 이름이 아니다. 물리량 3종이 각자의 학습 공간을 부를 때 쓰는 공통 인터페이스 이름에 가깝다. 세 모델 모두 physical_to_nondim / nondim_to_physical 을 갖고 있고, 안에 든 식만 서로 다르다. 렌더-grid 2종은 같은 일을 상수 한 줄로 끝내기 때문에 따로 이름을 두지 않았다.

조건 입력의 단위#

physical_info 는 같은 배열이라도 자리에 따라 단위가 다르다. 물리량-grid 에서 정규화 계수를 계산할 때 이 구분을 놓치면 계수가 틀어진다.

위치 단위
h5 원본, Dataset·Collator 의 raw_pinfos 원값 (풍속 26.0, 높이 mm, 센서 온도 °C)
모델 입력 batch_dict['input']['physical_info'] 정규화값 (building 은 풍속÷100·높이÷최대값, indoor 는 raw / PINFO_DIVISORS)
AE 의 최상위 batch_dict['physical_info'] 원값

모델은 정규화값에서 원값을 복원해 계수를 만든다 — building 은 풍속에 100 을 곱하고, indoor 는 PINFO_DIVISORS 를 되곱한다. _batch_pinfos() 가 위치 차이를 흡수한다. 렌더-grid 는 조건 입력을 정규화 계수에 쓰지 않으므로 이 구분이 필요 없다.

모델별 차이#

공통 구조는 위에서 다뤘으니, 여기서는 모델마다 다른 부분만 본다. 먼저 다섯을 나란히 놓고 무엇이 들어가서 무엇이 나오는지부터 확정하고, 그 다음에 모델별로 설명이 필요한 것만 따로 본다.

proximity_mask 는 2D 슬라이스에 z 방향 맥락을 주는 채널이다. 각 화소에서 형상이 있는 가장 가까운 아래 슬라이스와 위 슬라이스까지의 거리를 재고 그 역수를 넣는다. 그래서 두 채널이다. 한 장짜리 단면만 보고는 알 수 없는 "이 화소가 건물 바로 위인가, 한참 위인가" 를 이것이 알려준다.

정답 필드는 왜 input_fields 에 들어 있나

설정의 input_fields 는 신경망 입력 목록이 아니라 h5 에서 읽어올 키 목록이다. pressure·velocity 같은 이름이 거기 있는 것은 정답으로 쓰기 위해 읽는다는 뜻이고, Collator 가 그것들을 truth 로 갈라낸다. 신경망의 forward(mask, physical_info) 는 기하 입력과 조건만 받는다.

깊이 경로 (3D)#

3D 회귀는 위 표와 두 군데가 다르다. 슬라이스를 D 장씩 묶어 (b,c,D,h,w) 로 다룬다.

2D 3D
기하 입력 domain_mask + proximity_mask = 3채널 domain_mask 1채널만. 깊이 축이 실제로 있으니 z 맥락을 대신 넣어 줄 이유가 없다
추가 입력 없음 context — 정답 슬라이스 일부를 그대로 넣는다. depth_mask 가 1 인 자리만 남기고 나머지는 0
푸는 문제 조건에서 단면 한 장을 만든다 주어진 슬라이스 사이를 메운다

그래서 3D 회귀는 조건 생성기가 아니라 깊이 방향 보간기다. 학습할 때는 몇 장을 줄지 (depth_mask) 샘플마다 새로 정하고, 평가할 때는 창을 옮겨 가며 케이스 전체를 복원한다.

aicfd-building-physical#

가장 많은 모델군을 갖는다. contour 는 공간을 함께 들고 다니는 ContourDict 로 다루고, physical ↔ nondim ↔ {edm, ldm} 을 샘플별 계수로 왕복한다.

Latent 계열은 AE 두 개(도메인·contour)를 불러 nondim → latent → ldm 으로 인코딩하고, 평가 때만 디코더를 쓴다. 3D 모델은 contour 에 깊이 축을 더한 (b,c,D,h,w) 를 다룬다 — 깊이 경로 참고.

fluid 영역은 obj 단면을 z 슬라이스마다 래스터화해 만든다. 이 방법이 성립하는 이유는 외부 유동이기 때문이다 — 해석 영역이 풍동 상자이고 건물이 그 안의 장애물이라 "solid = obj 내부"가 유체의 여집합과 정확히 일치한다.

aicfd-indoor-physical#

단일 사무실 형상이라 모델·각도 축이 없다. 예측 필드는 velocity 와 temperature 이며 온도는 섭씨로 저장한다.

항목 값
형상 data/geo/260602_officeroom_r0_S.obj 하나. 모든 케이스가 같은 bounding box
케이스 21개
슬라이스 케이스당 13장, z = 0.2 ~ 2.6 m (0.2 m 간격)
격자 216 × 153 화소, 화소당 0.02 m

좌표계는 해석 결과의 로컬 프레임(최소 코너가 원점)을 따르고, 전처리가 obj 를 그 프레임으로 평행이동한다. z 는 양쪽이 같은 기준이라 그대로 쓴다. gt_max_height.txt 에 기록되는 216 은 contour 의 최대 변 길이(화소)이며, pad 캔버스 크기는 이 값보다 커야 한다.

  • 캔버스: 216×153 도메인을 256² 캔버스에 채워 넣는다(crop 이 아니라 pad). 학습은 임의 위치, 평가는 좌하단 고정.
  • fluid 마스크: domain_mask/255 를 연속값 마스크로 써서 정답과 예측 양쪽에 곱한다. 경계는 0~1 사이, pad 영역은 0 이다.
  • 조건 입력: 모델은 5점 관측에서 전체 장을 복원하는 보간기다. 엑셀 조건표(풍속·발열량·평형온도)는 실시간에 관측할 수 없어 입력에서 제외돼 있다. 남은 것이 입출력 사양 의 6채널이다.
  • 정규화: 풍속이 입력이 아니므로 기준 풍속 구간이 없다. 채널당 전역 scale 하나 + 온도 bias.

fluid 영역은 obj 그룹별 단면 래스터와 CFD 점군 bounding box 의 교집합이다. 설계 근거는 fluid 영역 정의 참고.

경계 화소의 온도는 물리값이 아니다

마스크가 전처리(절대 온도 공간)와 Collator(ΔT 공간) 두 곳에서 곱해지고 두 공간의 원점이 다르다. 그래서 반투명 경계 화소를 inverse transform 한 값은 CFD 값도 저장값도 아니다. 예측과 정답이 같은 경로를 지나므로 metric 과 디지털 트윈은 서로 일관되지만, 그 화소 하나의 값 자체는 물리 온도가 아니다. velocity 는 bias 가 0 이고 벽면 값도 0 이라 영향이 없다.

온도 단위는 원본 .ip 만 켈빈이고, 전처리에서 섭씨로 바꾼 뒤로는 저장·metric·출력이 모두 섭씨다. nondim 공간은 온도차라서 켈빈과 섭씨가 같다.

aicfd-building-pixel#

aicfd-building-physical 과 같은 모델군을 갖되 target 이 렌더 이미지다. 물리 단위 공간이 없고 정규화가 상수이므로 ContourDict 도 샘플별 계수도 없다. 정규화 상태를 갖는 것은 EDM/LDM 뿐이고 그 계수는 checkpoint 에 저장된다.

aicfd-nasal-pixel#

aicfd-building-pixel 에서 회귀 2D·3D 만 남긴 부분집합이다. 확산도 AE 도 없고 정규화 상태 자체가 없다 (3D 는 깊이 경로). 가장 작은 grid 모델이라 공통 코드 변경을 먼저 확인해 보기 좋다.

aifem-nasal-physical#

유일한 mesh 모델이다. vertex 수가 가변인 삼각형 표면을 그대로 받아 vertex 별 스칼라 WSS 를 예측한다. 격자도, 화소 공간도, Collator 도, 확산·AE 도 없다.

h5 (verts/faces, 면 중심 WSS, 면적, 유속, cavity 부피, vertex 별 단면적)
  → normalize_positions → get_operators (Laplacian, 질량, eigenpair, gradient operator)   [디스크 캐시]
  → physical_to_nondim → 면 값을 면적가중으로 vertex 에 뿌림
  → net(features, 기하 연산자, FiLM(유속, 단면적)) → vertex 별 예측
  → nondim_to_physical → metric (WSS 단위)
  • input scalar: 좌표, HKS, 또는 둘 다. HKS 는 디스크 캐시.
  • 조건화: 단면적을 조건으로 같이 주는 이유는 WSS 를 정하는 국소 유속이 유량÷단면적이기 때문이다. 단면적은 벽 건너편까지 봐야 나오는 값이라 표면 위의 확산만으로는 복원되지 않는다. cavity 안에서 조화 퍼텐셜을 풀어 등위면 조각의 넓이를 vertex 마다 스칼라 하나씩 주고, 그 값으로 조건화한다 (구하는 법은 전처리, 조건 구성은 입출력 사양). 유량이 절대 단위로 들어오므로 단면적도 절대 단위로 두어야 둘의 비가 유속이 된다.
  • 기하 연산자: Laplacian eigendecomposition 이 가장 오래 걸리므로 (verts, faces) 해시를 키로 디스크 캐시한다.
  • 배치 크기는 1 이다. 여러 샘플을 묶어야 하면 accum_steps 로 기울기를 누적한다.
  • 정밀도: 기하·확산 연산은 float32 고정, MLP 만 자동 혼합정밀도.
  • 크기 계수는 해석 설정값에서 정한다. ρ, ν, 라벨을 질량유량으로 바꾸는 상수가 전 케이스 공통이라 셋을 곱해 두면 target 이 dimensionless group 그 자체가 되고, 통계가 들어갈 자리가 없다.

평가 결과는 vertex 별 WSS 스칼라와 turbo 색을 담은 이진 PLY 로, 예측과 정답을 같은 색 범위로 나란히 저장한다.

표면 flux 확장#

이 모델의 대상은 벽면 flux 장 전반이고 WSS 는 그중 첫 필드다. 수증기 질량 flux 와 벽면 열 flux 가 추가될 예정이다. 현재 구현은 단일 필드로 고정돼 있어 확장 시 다음이 바뀐다.
